The schema has no `version:` field and the package's `_version.py` reports
`0.0.0`, so the version comes only from the distribution metadata (`0.2.0`,
via `importlib.metadata`). The packaged and monolith schemas are
**semantically identical**: same 30 classes with the same induced slots (name,
range, multivalued, required), same 30 enums with the same permissible values,
same prefixes except the monolith adds `shex` and `xsd` from merging. File
hashes differ only because one is modular. `check-drift` should compare
semantically, not by file hash.

Join-table column names are generated and irregular: owner side is
`<Class>_<pk>` (mixed case, e.g. `Study_study_id`); value side is `<slot>`,
`<slot>_id`, `<slot>_concept_curie`, or `<slot>_<target pk>`
(`file_id_file_id`, `sample_id_sample_id`). Derive them from metadata; never
build them by string pattern.

## Coded columns

Three different mechanisms, which matters for R9 and the ConceptRegistry:

1. **FK to `Concept`** (DB-enforced): `Subject.subject_type`,
   `Demographics.{sex,ethnicity,vital_status}`, `FamilyMembership.family_role`,
   `FamilyRelationship.relation`, `BiospecimenCollection.{site,spatial_qualifier,laterality}`,
   `Sample.quantity_unit`, `Aliquot.{quantity_unit,concentration_unit}`,
   `SubjectAssertion.value_unit`, `File.data_category`, plus the six Concept
   join tables above. `ConceptRelationship.target_concept_curie` too.
2. **Native PG enum** (16 columns, 14 distinct types; values are curies, no
   Concept FK): `AccessPolicy.{data_use_permission,data_use_modifier}`,
   `Family.{family_type,consanguinity}`,
   `SubjectAssertion.{asserter_type,assertion_source_type}`,
   `Sample.availability_status`, `Aliquot.availability_status`,
   `File.{format,data_type,availability}`, `BiospecimenCollection.method`,
   `HashDigest.hash_type`, `Assay.assay_type`, and the two StudyMetadata join
   tables. `EnumAvailabilityStatus` and `EnumDataSourceType` are each shared by
   several columns (one PG type each). Large ones: `EnumAssayType` 1803,
   `EnumEDAMDataTypes` 949, `EnumEDAMFormats` 632, `EnumSampleCollectionMethod` 136.
3. **Plain text uriorcurie** (no enforcement): `Subject.organism_type`,
   `Sample.sample_type`, `Sample_processing`, `Sample_storage_method`,
   `Study_program` (values are full URIs, e.g. `https://www.nih.gov/include-project`).

## Constraints

- **No unique constraints and no indexes** anywhere besides PKs.
- NOT NULL matches LinkML `required` exactly for single-valued slots (no
  mismatches either way).
- Required **multivalued** slots (R2), each a join table: `Study.{program,
  principal_investigator, contact}`, `StudyMetadata.{participant_lifespan_stage,
  study_design, clinical_data_source_type, data_category, research_domain}`,
  `Demographics.race`, `VirtualBiorepository.contact`. (DESIGN R2's example
  list omits `VirtualBiorepository_contact`; R2 is generic, so no change needed.)
- Record-mixin `study_id` / `access_policy_id` are nullable everywhere (R1
  enforces them).

## FK cycles

`metadata.sorted_tables` reports exactly one unresolvable cycle:
**`Study.do_id` ↔ `DOI.study_id`**. Self-references: `Study.parent_study`,
`Sample.parent_sample_id`. DESIGN §6.1 also lists Investigator ↔ Study, but
that's not a table-level cycle (`Investigator.study_id` → Study, and the join
tables point at both), so ordinary FK ordering handles it.

## Other notes for later phases

- No class is a `tree_root`, so there's no container class. YAML validation
  (4.3) must use `--target-class` per file.
- `File.slots` lists `format` twice (MODEL_ISSUES #4); induced slots and the
  SQL table have it once, so it only affects code that iterates raw `slots`.
  Use `class_induced_slots`.
- `fmGlobalID`, `msGlobalID`, `pdGlobalID` descriptions say "Dewrangle __ global
  ID" (placeholder text).

## Proposed decisions (for CHECKPOINT A)

1. **Reference tables `Synonym`, `ConceptRelationship`, `DeprecatedConcept`**:
   create them, leave them empty, export header-only CSVs. Settings get two
   lists: `exclude_tables` (not created: `Any`, `Record`, `Record_external_id`)
   and `empty_tables` (created, no rows, drift test accepts them). A Synonym
   factory can come later if the dbt staging needs synonyms.
2. **Nullable linking FKs**: `Encounter.subject_id`, `SubjectAssertion.subject_id`,
   `Sample.biospecimen_collection_id`, `Aliquot.sample_id` are nullable, but
   a NULL makes the row an orphan with no FHIR subject. Proposal: extend R4
   ("reachability") to require all four, alongside `BiospecimenCollection.encounter_id`.
